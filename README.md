# 护理用药提醒

一个面向护理专业学习与日常照护场景的轻量级用药提醒网页。使用原生 HTML、CSS、JavaScript 编写，不依赖框架和后端，打开页面即可添加药品、设置每日提醒并记录当天是否已服用。

> 本项目是前端练习与轻量辅助工具，不能替代医嘱、护理核对流程或医院信息系统。实际用药请严格遵循医生和带教老师的要求。

- **本地演示地址**：<http://localhost:8000>
- **直接打开**：[index.html](./index.html)
- 当前项目暂未部署公网版本，以上为本地演示地址，需要项目目录中的本地服务保持运行。

## 项目背景

护理专业的学习和照护工作中，给药是高频且需要高度准确的环节。药品名称、剂量、给药时间和注意事项较多，仅依靠记忆或纸质记录容易出现漏服、重复提醒或交接不清。

本项目从一个护理专业学生的日常场景出发，做一个简单、清晰、适合手机使用的用药提醒工具：

- 用结构化数据记录药品名称、剂量、提醒时间和备注；
- 每天在固定时间提醒，减少漏服；
- 通过「已服用」按钮记录当天的执行情况；
- 数据保存在浏览器本地，无需注册、无后端、不会上传个人数据；
- 作为护理信息化、前端交互设计和 Web Notification API 的学习作品。

## 功能

- **今日概览**：实时统计今日应服、已服和待服数量，并显示完成进度，添加、删除或标记已服后自动更新。
- **添加药品**：填写药品名称（必填）、剂量、提醒时间（必填）和备注。
- **用药清单**：按提醒时间从早到晚排序，展示时间、剂量、备注和当天状态。
- **编辑药品**：点击清单中的「编辑」回填表单，保存后更新原记录而不新增；支持取消编辑。
- **删除提醒**：删除前二次确认，并同步更新本地数据。
- **本地持久化**：使用 `localStorage` 保存，刷新或重新打开页面后数据仍然存在。
- **每日定时提醒**：每分钟检查一次当前时间，到点后触发提醒，同一天不会重复提醒。
- **系统通知**：提供「开启通知」按钮，申请浏览器通知权限；授权后通过 Notification API 发送系统通知。
- **页面内兜底提醒**：未授权通知、浏览器不支持通知或通知发送失败时，在页面顶部显示醒目的提醒条。
- **已服用记录**：点击「已服用」标记当天服药状态，状态变为「今日已服」，再次点击可撤销。
- **每日自动重置**：日期变化后，提醒状态和「已服用」状态会自动恢复为新一天。
- **移动端适配**：响应式布局，适合手机操作；表单使用 16px 字号避免 iOS 自动放大。
- **基础无障碍**：表单错误提示、按钮 `aria-label`、状态标签和 `role="alert"` 提醒区域。

## 技术栈

- **HTML5**：语义化页面结构、表单原生校验属性、`hidden` 属性。
- **CSS3**：CSS 变量、Flexbox、CSS Grid、媒体查询、`:focus-visible`、`prefers-reduced-motion`。
- **原生 JavaScript（ES6+）**：
  - 数组与对象数据处理；
  - `Intl.DateTimeFormat` 显示中文时间和日期；
  - 定时器与整分钟对齐调度；
  - 事件委托处理列表按钮；
  - `async/await` 处理通知权限请求。
- **Web Notification API**：系统通知、权限申请和通知点击后聚焦页面。
- **Web Storage API**：`localStorage` 保存用药清单与当天状态。
- 无框架、无构建工具、无后端依赖。

## 使用说明

1. **开启通知**：点击页面顶部的「开启通知」，在浏览器弹窗中允许通知。授权成功后按钮会显示「已开启」。
2. **添加药品**：填写药品名称、剂量、提醒时间和备注，点击「添加提醒」。
3. **等待提醒**：页面保持打开，到达设定时间后会发送系统通知；如果通知权限未开启，则显示页面内提醒。
4. **记录服药**：服药后点击对应药品的「已服用」，状态变为「今日已服」。
5. **撤销误操作**：已标记的药品会显示「撤销」，点击可取消当天标记。
6. **编辑药品**：点击清单中的「编辑」，表单会自动回填；修改后点击「保存修改」，或点击「取消编辑」放弃修改。
7. **删除药品**：点击「删除」，确认后从清单和本地存储中移除。如果删除的是正在编辑的药品，页面会自动退出编辑模式。

## 数据设计

数据保存在 `localStorage` 的 `nursing-medication-reminders-v1` 键中，结构如下：

```json
[
  {
    "id": "唯一标识",
    "name": "阿司匹林肠溶片",
    "dosage": "1 片",
    "time": "08:30",
    "note": "饭后服用",
    "lastNotified": "2026-11-12",
    "lastTaken": "2026-11-12"
  }
]
```

字段说明：

- `lastNotified`：最近一次提醒的日期，用于避免同一天重复提醒。
- `lastTaken`：标记为已服用的日期，日期变化后自动视为新一天待服用。
- 兼容旧字段 `takenOn`：旧数据没有 `lastTaken` 时，读取阶段会把 `takenOn` 自动迁移为 `lastTaken`；两个字段都缺失时按未服用处理。

## 关键实现逻辑

### 1. 整分钟检查

提醒不是在页面打开后固定等待 60 秒，而是根据当前秒数计算距离下一整分钟的时间：

```js
var elapsedInMinute = now.getSeconds() * 1000 + now.getMilliseconds();
var delay = 60000 - elapsedInMinute + 30;
```

到达整分钟后执行检查，并重新安排下一次检查，避免计时漂移。页面从后台回到前台时也会重新检查。

### 2. 防重复提醒

到点时只处理同时满足以下条件的药品：

```js
medicine.time === currentTimeKey &&
medicine.lastNotified !== today &&
medicine.lastTaken !== today
```

触发后把 `lastNotified` 更新为当天日期并保存。这样同一天不会重复提醒；第二天日期变化后会自动恢复。如果当天已经标记「已服用」，到点也不会再提醒。

### 3. 系统通知与兜底

如果浏览器已授权通知权限，则通过 `new Notification(...)` 发送系统通知；否则调用页面内的提醒条。即使通知权限被拒绝、浏览器不支持或构造通知失败，用户仍然能在页面里看到到点提醒。

### 4. 已服用状态

点击「已服用」时，将当天日期写入 `lastTaken`。渲染列表时比较 `lastTaken` 与今天：

- 相同：显示「今日已服」，按钮变为「撤销」；
- 不同：显示「待提醒」或「已提醒 · 待服用」。

### 5. 今日概览

`updateOverview()` 会在每次调用 `renderMedicines()` 时执行，根据 `lastTaken` 与今天的日期计算：

- 应服：清单中的药品总数；
- 已服：`lastTaken` 等于今天的药品数量；
- 待服：应服数减去已服数；
- 进度：已服数 / 应服数。

因此添加、删除、标记已服和撤销操作都会自动更新概览。旧数据没有 `lastTaken` 字段时，加载阶段会兼容旧的 `takenOn` 字段或自动补为空字符串，并按“今日待服”统计，不需要手动迁移数据。

### 6. 本地数据安全

列表内容使用 `textContent` 创建 DOM 节点，不把用户输入直接作为 HTML 插入，降低 XSS 风险。所有数据只保存在当前浏览器，不会上传服务器。

## 测试提醒的方法

### 方法一：设置下一分钟（推荐）

1. 添加一条提醒，时间设置为当前时间的下一分钟。
2. 保持页面打开，等待到点。
3. 已授权通知时观察系统通知；未授权时观察页面内提醒条。

### 方法二：修改系统时间（可选）

1. 先添加一条未来时间的提醒并保持页面打开。
2. 在操作系统设置中把时间调整到提醒时间前一分钟。
3. 等待提醒触发。
4. 测试完成后恢复系统自动对时。

> 修改系统时间可能影响其他程序和日志，条件允许时优先使用方法一。提醒依赖页面中的 JavaScript 定时器，页面关闭后不会继续工作。

## 已知限制

- **页面需要保持打开**：提醒依赖页面内的计时器，关闭浏览器或关闭标签页后不会继续提醒。
- **后台节流**：手机浏览器和部分桌面浏览器会节流后台标签页的定时器，长时间切到后台可能导致提醒延迟；回到页面时会补做一次检查。
- **通知权限限制**：系统通知需要用户授权；部分浏览器对 `file://` 页面、iOS Safari 和隐私模式有额外限制，建议使用 `localhost` 或 HTTPS。
- **数据仅在本机**：清除浏览器站点数据、更换浏览器或更换设备后，记录不会自动同步。
- **单次每日提醒**：当前每条药品每天只有一个提醒时间，暂不支持一天多个时间点。
- **非医疗设备**：本项目只作为提醒辅助，不提供药物相互作用判断、剂量建议或临床决策支持。
